## ข่าวนี้เกี่ยวกับการทดลองอย่างไร

[AMD วันที่ 20 ตุลาคม](https://newsroom.amd.com/news/amd-intel-collaborate-simplify-ai-development-on-x86-cpus-pytorch/) วางแผนรวม ZenDNN เข้า oneDNN สำหรับ PyTorch CPU และวาง ACE ไว้ในอนาคต จึงต้องแยกแผนนี้ออกจากแพ็กเกจที่ rig ใช้อยู่

ข้อวิเคราะห์คือชื่อไลบรารีไม่ใช่รายละเอียด benchmark ต้องรู้ว่าโค้ดเลือก backend ใดและติดตั้งอะไรจริง อ่าน[release notes ของ oneDNN](https://www.intel.com/content/www/us/en/developer/articles/release-notes/onednn/2026.html) แล้วเก็บข้อจำกัดที่เกี่ยวข้องกับ environment ไม่เปลี่ยนหลายค่าเพื่อไล่ตัวเลขที่สวยกว่า

## บันทึกอะไรไว้ในผลการทดลอง

แบบบันทึกนี้ช่วยให้คนอื่นรันงานเดิมได้ โดยไม่ได้ตั้งผลที่คาดหวังให้ CPU ยี่ห้อใด

| สิ่งที่ตรึง | สิ่งที่ต้องเขียน | เหตุที่ต้องเก็บ |
| --- | --- | --- |
| Input และโมเดล | รุ่น ไฟล์ precision | แยกคุณภาพจากความเร็ว |
| Runtime | แพ็กเกจและ backend จริง | รู้ว่าเส้นทางใดทำงาน |
| CPU | Thread กับงานเบื้องหลัง | ลดตัวแปรระหว่างรอบ |
| วิธีวัด | Warm-up และรอบจริง | ไม่ปนเวลาเริ่มระบบ |

## จะใช้ผลปรับสเปก rig อย่างไร

บันทึกทั้งงานที่ผ่านและข้อผิดพลาด ถ้าต้องเปลี่ยนแพ็กเกจให้เก็บผลก่อนและหลังแยกกัน ตัดสินจากโปรเจกต์ที่คุณต้องทำ ไม่ใช่ kernel ตัวเดียว

ใช้[ตารางโมเดลกับหน่วยความจำ](/models/) กำหนดงาน แล้วแนบ lockfile และคำสั่งรันเมื่อคุยเรื่องอัปเกรด rig
