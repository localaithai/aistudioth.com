เริ่มจากโปรเจกต์เล็กที่เรียกส่วนสำคัญครบ แล้วติดตั้งจาก manifest บนเครื่องใหม่ เก็บรายการที่ต้อง build เองหรือใช้วิธีเฉพาะ แทนการเริ่มจากการย้าย environment เดิมทั้งชุด

## ข่าวนี้ยืนยันอะไร

AI TOP AERO เปิดตัววันที่ 10 พฤศจิกายน ตามข่าว GIGABYTE วันที่ 11 พฤศจิกายน 2026 [ตามประกาศหลัก](https://www.gigabyte.com/press/news/2467) ประกาศ RTX Spark ก่อนหน้า [แหล่งข้อมูลอีกหน้าหนึ่ง](https://nvidianews.nvidia.com/news/nvidia-rtx-spark-pcs-available-today-a-new-beginning-for-windows-pcs) ให้บริบท Windows และ Grace/Blackwell แต่ยังต้องตรวจ dependencies ของแต่ละโปรเจกต์

## preflight จากติดตั้งถึงเรียกโมเดล

ตารางต่อไปนี้เป็นเกณฑ์ที่เราเสนอให้ใช้ตัดสินใจ ไม่ใช่ผลทดสอบที่ Mimir วัด

| จุดตรวจ | สิ่งที่บันทึก | ลองอะไรให้ผ่าน |
| --- | --- | --- |
| OS/architecture | รุ่น OS และสถาปัตยกรรม process | เครื่องมือที่เรียกไม่สลับ build โดยไม่รู้ตัว |
| Python packages | รุ่น wheel และของที่ build เอง | ติดตั้งใหม่จากรายการเดียวกัน |
| runtime | engine backend และ library build | โหลดโมเดลกับเรียกฟังก์ชันที่ต้องใช้ |
| workflow | แอป client และงานร่วม | รับไฟล์ เรียกโมเดล และเก็บผลได้ครบ |

## ทดสอบ model fit กับเครื่องมือแยกกัน

แนวทางที่เราเสนอคือเก็บผลสองตาราง ตารางหนึ่งบอกว่าโมเดลกับบริบทใดพอดี อีกตารางบอกว่าเครื่องมือใดทำงานบน stack นี้ได้ หากบังคับใช้ชื่อโมเดลเดียวอธิบายทุกอย่าง จะมองไม่เห็นปัญหาที่เกิดก่อนถึง inference

เมื่อ preflight ผ่านแล้วจึงวัดงานต่อเนื่องและภาระ agent เบื้องหลังด้วยค่าที่ตรึงไว้ ข่าวนี้ยังไม่ยืนยัน SKU หรือราคาไทย จัดรายการโมเดลที่ตั้งใจใช้กับ [แนวทาง model fit ของ AI rig](/models/)
