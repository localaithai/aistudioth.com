ผลที่เร็วขึ้นต้องกลับมารันซ้ำได้ เริ่มจากเก็บตัวตนของ engine และเงื่อนไขที่ทำให้มันผ่านการตรวจคำตอบ ก่อนนำตัวเลขไปเปลี่ยนสเปก AI rig

## NVIDIA เผยอะไรในคู่มือชุดนี้

วันที่ 23 ตุลาคม 2026 NVIDIA เผยคู่มือ Global Performance Tuner สองตอน อธิบายการค้นหา build route ภายใต้เกณฑ์ความแม่นยำ คู่มือตอนสองรายงานผลเฉพาะชุดทดสอบของผู้ผลิต และให้จูนใหม่เมื่อเปลี่ยนโมเดล shapes GPU หรือซอฟต์แวร์ นี่เป็นการเผยวิธีใช้งานฟีเจอร์ที่มีใน TensorRT 11.1 อยู่แล้ว

## เก็บไฟล์อะไรจึงจะกลับมาทดสอบได้

ตารางนี้เป็นข้อเสนอสำหรับจัดโฟลเดอร์ผลทดสอบของนักพัฒนา ไม่ใช่ผลวัดเครื่องจาก AI Studio TH

| สิ่งที่เก็บ | ผูกกับอะไร | ถ้าไม่มีจะตอบอะไรไม่ได้ |
| --- | --- | --- |
| Model revision และชุดข้อมูลเข้า | การรันครั้งนั้น | ทดสอบโมเดลเดียวกันหรือไม่ |
| Shapes และ batch | รูปแบบงานจริง | เร็วขึ้นเพราะเปลี่ยนขนาดงานหรือไม่ |
| เกณฑ์ตรวจคำตอบ | ผลอ้างอิงชุดเดิม | engine ที่เร็วขึ้นยังยอมรับได้หรือไม่ |
| Build route และ tuning cache | GPU กับ runtime ที่ใช้ | จะสร้างผลเดิมกลับมาอย่างไร |
| เวลา build และเวลา inference | engine ที่ถูกเลือก | ประหยัดเวลางานรวมคุ้มเวลาจูนหรือไม่ |

## จะตัดสินผลจูนบน rig ของตนเองอย่างไร

แยกเวลาค้นหาออกจากเวลารันงาน หากงานเกิดขึ้นครั้งเดียว การจูนนานอาจไม่ได้ลดเวลาจบงาน แต่ถ้า engine เดิมถูกเรียกซ้ำ ควรคำนวณจำนวนรอบที่ช่วยคืนเวลาจูนจากข้อมูลที่วัดได้จริง

เมื่อมี candidate ที่ผ่านเกณฑ์ ให้เก็บ baseline ไว้คู่กัน ทดสอบกับข้อมูลที่ไม่ได้ใช้เลือกเส้นทาง แล้วจดทั้งความคลาดเคลื่อนและเวลาที่ใช้ การเลือกเฉพาะรอบเร็วที่สุดโดยไม่บันทึกรอบที่ล้มเหลวจะทำให้ผู้อื่นประเมินความเสี่ยงของสูตรนั้นไม่ได้
