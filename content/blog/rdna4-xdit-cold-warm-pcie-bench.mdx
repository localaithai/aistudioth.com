อย่าเทียบจำนวนการ์ดโดยเปลี่ยนโหมดโหลดไปพร้อมกันโดยไม่จด หากรอบหนึ่งใช้ CPU offload แต่อีกรอบไม่ต้องใช้ ผลต่างอธิบายทั้งเรื่อง capacity และการแบ่งงาน ไม่ใช่ประสิทธิภาพข้าม GPU เพียงอย่างเดียว

## ข่าวนี้ยืนยันอะไร

AMD ลงวิธีรัน xDiT บน RDNA 4 หลายการ์ดวันที่ 2 พฤศจิกายน 2026 [ตามประกาศหลัก](https://rocm.blogs.amd.com/artificial-intelligence/diffusion-xdit-rdna4/README.html) บท FP8 GEMM ก่อนหน้า [แหล่งข้อมูลอีกหน้าหนึ่ง](https://rocm.blogs.amd.com/software-tools-optimization/rdna-fp8-gemm/README.html) เป็นบริบทระดับ kernel และไม่ได้วัด latency ของ pipeline สร้างภาพทั้งหมด

## ชุดรันที่ทำให้แยกสาเหตุได้

ตารางต่อไปนี้เป็นเกณฑ์ที่เราเสนอให้ใช้ตัดสินใจ ไม่ใช่ผลทดสอบที่ Mimir วัด

| ชุดทดลอง | คงค่าอะไร | รายงานอะไร |
| --- | --- | --- |
| cold | container/model และ cache เริ่มต้น | download compile load และ generation แยกช่วง |
| warm | process และ cache พร้อมแบบเดียวกัน | latency ต่อ request กับ VRAM สูงสุด |
| กระจายหนึ่ง request | seed resolution steps และ precision | วิธี sharding และต้นทุนสื่อสาร |
| request อิสระ | จำนวนงานและรูปแบบผลเท่ากัน | throughput รวมกับเวลาของแต่ละงาน |

## เก็บคุณภาพภาพไว้ข้างตัวเลขเวลา

เราเสนอให้บันทึกภาพผลลัพธ์คู่กับ config ทุกครั้งที่เปิด quantization หรือ step caching กำหนด prompt ที่ตรวจรายละเอียดได้ก่อนทดลอง แล้วระบุว่าความต่างระดับใดยอมรับได้ อย่าเลือกเฉพาะภาพที่ดูดีมาอธิบายทั้งชุด

เก็บผัง PCIe และภาระ host RAM ของเครื่องไว้ด้วย เพื่อให้คนอื่นรู้ขอบเขตการทำซ้ำ งานนี้เป็นการทดสอบเครื่องมือภายนอก ไม่ใช่บริการ Image/Video Studio ของ Mimir ดูแบบจัดผลใน [หน้ารวบรวม benchmarks](/benchmarks/)
