# Design log, 2026-10-15

## React Bits on the build memory figures

**Context.** The user requested React Bits where applicable and design polish
across the portfolio. This request supersedes the former framer-motion-only
rule in `AGENTS.md`.

**Chosen.** `ScrambledText` marks the existing Latin-only memory capacities in
`BuildsSection`, including `128 GB` and `2x 128 GB`. The existing section island
hydrates on visibility on the home page and on load when it opens `/builds`.
The effect decodes the capacity on entry and responds to nearby pointer movement;
Thai suffixes stay outside it. Real text renders on the server, an unchanged
screen-reader copy supplies its accessible text, and reduced motion leaves the
readout static. No additional island or hero canvas is needed.

**Rejected.** `GlitchText` would suggest unreliable specifications;
`CircularGallery` would make the machine options harder to compare;
`Noise` would obscure the existing clean desk photography without explaining
the product.

## Keep the specification readable before hydration

**Chosen.** The page transition lifts without fading, and section entrances use
the visible server output as their default. Reduced motion restores sections to
their resting state. Static base and component styles sit in Tailwind layers so
utilities control surfaces, dimensions and colour. Thai and mixed labels keep
normal spacing, with more room for vowel and tone marks across the type scale.

Build machine images form a compact phone grid. The mobile menu exposes its
expanded state, supports Escape and restores focus; navigation identifies the
current page. Links and actions have 44px targets and visible blue focus. Blog
summary and callout panels use complete borders, and article paragraphs inherit
the blog's readable ink and line height. Copy, URLs, metadata and desk photography
stay intact.
